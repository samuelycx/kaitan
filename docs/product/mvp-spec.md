# 开摊 · MVP 规格

产品名：开摊  
依据：[2026-09-04 领域调研简报](../research/2026-09-04-domain-brief.md)

这不是市集报名工具。市集是限时场次；这里是 **每天开门的固定经营场所**：把原来散在路边、不合规的摊主收到一个点上，持证、定时、定点做生意。

第一城：跟已能管起来的场所走（2026-09-04）。  
场所画像：每天营业，少量收取摊位 / 管理费。  
方向确认（2026-09-04）：经营点 + 日报名占位 + 向管场收钱、名单只显示占到位的，这个方向对。  
下一步（2026-09-06）：见 [下一步优化](next-steps.md)。原型已跑通，进真实经营点前要补触达和到场状态。  
目标形态（2026-09-04）：C / 摊主 / 管场 **三个小程序**。没证照的摊只展示，点单付款在摊上；证照办齐的才上架菜品、开放小程序点单。管场规划见 [三端形态](three-apps.md)。

## 要验证的一句话

入驻不等于当天有位。所有摊主每天在固定时点前报名；不报，当天不保证有摊位。管理员看到谁占到、谁没报、还空几位。

## 三角色主循环

1. **管场**：常驻场所（营业时段、每日报名截止、总摊位数、月管理费）。到点截止报名。看今日占位、候补、未报名。
2. **摊主**：申请从路边迁入，成为在册摊主。每天截止前报名占今日摊位。不报没有位。不是报下一场市集。
3. **逛摊**：看今晚谁占到了摊位。未报名的不出现在今晚名单。

经营工具这一期只做每日报名占位。社区不做。支付不做。代收不做。

## 调研落到规划（2026-09-04）

- **今晚名单是供给，不是内容。** 腾讯小摊地图死在新鲜度；C 端怕跑空。名单只来自截止前报名，未报的不展示。
- **第一年向管场收钱。** 摊主已经在付管理费，不再收 SaaS；逛摊不收费。代收等信任和资质够了再谈。
- **不跟摊有序抢免费位。** 找每天开门、少量收费的疏导 / 商场 / 承包点。
- **合法点上的工具，不是游击导航。** 政策主旋律是疏导 + 规范；食品摊要证，平台不办证、不担保。
- **冷启动搬一个点的微信群点名。** 不拉全国摊主。下一周验证的是「群里报数」能不能换成每日报名。
- **记账、进货、社区、全国地图不做。** 痛真实，付费和新鲜度都撑不住。

## 做 / 不做

做：一个场所的入驻、每日报名、到点截止、空位、今晚占位名单。  
不做：按日期发布「一场市集」、月租占死摊位、全国摊位地图、内容社区、供应链、躲避城管的游击导航、原生 App。

## 本周交付

浏览器里走完：在册摊主报名今日 → 管场到点截止 → 未报名的今晚没有摊位 → 逛摊只看到占到位的。数据在本机。演示截止默认 15:00。

## 下一周

把真实经营点的微信群点名换成每日报名；摊主同时确认今晚菜单，C 端先看「今晚有什么」，仍不收款。准备企业主体，再拆三个小程序。点单付款要等摊主办好个体户和自己的微信支付商户号。货款进摊主商户，不进经营点。
