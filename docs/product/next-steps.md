# 开摊 · 下一步优化

日期：2026-09-06  
依据：[MVP 规格](mvp-spec.md)、[三端形态](three-apps.md)、[调研简报](../research/2026-09-04-domain-brief.md)  
范围：Web 原型跑通之后，进真实经营点之前该补的东西。不改变方向，只补缺口。  
排期：见 [四周排期](plan-2026-09.md)。

## 一句话

机制做对了，但要验证的那句话现在验证不了。差的不是功能数量，是 **触达** 和 **到场状态** 这两样。

「入驻不等于当天有位」要成立，摊主得知道该报名了，顾客得看到的是真在场的摊。这两件缺一件，下周去真实经营点做替换，结果会是摊主继续在群里报数、管场自己代录进系统。那不算验证通过。

## 一、最挡路的三件事

### 1. 没有任何主动触达

整个每日报名循环的前提，是摊主自己记得在截止前打开产品。而它要取代的微信群点名，最大的优势恰恰是群消息会弹出来。摊主收摊晚、白天备货，不会主动开一个工具。

这不是体验问题，是这个产品成不成立的问题。

要补的提醒，按重要性：

| 提醒谁 | 什么时候 | 说什么 |
| --- | --- | --- |
| 摊主 | 截止前一小时 | 今天还没报名，过点没位 |
| 摊主 | 审核有结果时 | 进场准了 / 没过 |
| 管场 | 截止时间到 | 今天几人报名、几个空位 |
| 摊主 | 有新订单时 | 有人点单了（等点单真正开放后） |

载体是小程序订阅消息。现在还在 Web 阶段发不出去，但流程设计从现在起就要按「会有提醒」来排，不要设计成依赖摊主主动查看。

### 2. 对顾客的核心承诺没有兑现

调研里 C 端第一痛点是跑空，产品的卖点写的是「只看今晚占到位的摊」。

但顾客现在看到的是 **报上名的摊，不是已经到场的摊**。摊主报了名没出摊，管场那边已经标了未到，顾客端照样显示。顾客可能正是奔着这个摊去的，然后扑空 —— 正好踩中产品声称要解决的那个坑。

到场信息管场端已经有了，只是没有传到顾客端。这是现在最容易兑现、也最该先兑现的一件事。

配套要想清楚两件事：

- 摊主到场怎么确认。让摊主自己按一下最轻，管场逐个点效率低。
- 还没到场的摊，顾客端是完全不显示，还是显示成「还没开摊」。倾向后者：顾客出门前就想知道今晚谁会来，完全隐藏反而降低了名单的价值。开摊了再变成可前往。

### 3. 截止时间是假的

页面上写着今日 15:00 前报名，但真正决定截不截止的是管场手动按一下按钮。管场忘了按，报名一直开着；提前按了，说好的时间就不作数。

而「到点截止」是这个产品对摊主立的唯一规矩。规矩必须比人可靠，否则摊主不会信它，会退回去直接问管场本人 —— 又回到微信群。

改法：截止时间自动生效，管场那个按钮只保留提前截止的用途。

## 二、结构上缺的一块：没有日期

产品目前所有数据都是「今天」，开启下一天就把昨天抹掉。带来三个后果：

- 管场回答不了「这个摊主这个月放了几次鸽子」。而这正是决定还要不要给他位置的依据。政府那套疏导点系统用信用分管这件事，是因为这确实是管场每天在做的判断。
- 管场收月费时没有依据，只有一个交没交的开关，没有交费记录。而月费是第一年唯一的收入来源。
- 摊主看不到自己的经营轨迹，产品对他永远只是每天要打卡的负担，没有沉淀。

补日期不等于做记账。只要每天的报名、到场、放鸽子、成交留档，上面三个问题就都能回答。记账、进货仍然不做。

## 三、先做什么

按顺序，前三条决定验证能不能成立：

1. 顾客端区分已到场和未到场，摊主自己确认到场。
2. 截止时间自动生效，手动按钮降级为提前截止。
3. 报名提醒与审核结果提醒。要等小程序，但流程现在就按有提醒来设计。
4. 每天留档，管场能看到某个摊主的出摊率和放鸽子次数。
5. 摊主报名简化到一步。现在要先选格子再报名，而绝大多数摊主每天就是要昨天那个位置；默认续昨天的位置，想换再点场图。

## 四、先不做什么

即使看起来顺手，这几件现在都不做：

- **点单付款不再往前推。** 它卡在摊主要办个体户和自己的支付商户号，这不是产品能解决的。现有的可点单摊位继续当演示。
- **评价体系不加功能。** 一个点上十来个摊，天天见面，评分信息量很低，反而会给管场制造矛盾。
- **多经营点、跨城市不碰。** 第一个点真跑起来再说。不做全国地图这条纪律要守住。
- **记账、进货、社区** 维持不做。

## 五、遗留的产品决策

抢同一个格子输掉的摊主，目前会保留这个格子作为候补意向。就算场上还有别的合适空位，他也不会被自动安排过去，要等那个格子被释放。

现在按「他就是想要这个位置」处理。真实场景里摊主更可能是「有位就行」，进点后要跟管场确认一下再定。

## 六、这一步之后的判断标准

下周去真实经营点，验证通过的标准不是功能跑通，是这两条：

- 截止那一刻，报名名单和管场心里的名单一致，管场不需要再去群里核对。
- 顾客端当晚显示的摊，和实际站在场上的摊一致。

任何一条不成立，先修这一条，不加新功能。
